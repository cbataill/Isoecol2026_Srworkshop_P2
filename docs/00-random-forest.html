0. How random forest works

From one decision tree to a forest, and to an isoscape

The ideas behind the model we build today
Modified

October 10, 2026

In this section
  • You’ll learn: how a regression tree splits the data, why one tree is not enough, and how bagging and random forest fix it
  • You’ll need: nothing to run: this page has no code for RStudio
  • Time: about 15 minutes

Overview

In the talk, we saw that bioavailable ⁸⁷Sr/⁸⁶Sr varies at many scales: continental terranes, regional bedrock, atmospheric gradients (dust, sea salt) and local sedimentary features. No single map captures all of them. A random forest learns how ⁸⁷Sr/⁸⁶Sr relates to many maps at once (geology, climate, soils, atmospheric deposition…), and then predicts it everywhere.

✅ Why random forest for Sr?
  • Combines many geospatial layers seamlessly
  • Captures non-linear relationships and interactions
  • Can map multiscale patterns of bioavailable ⁸⁷Sr/⁸⁶Sr
  • More accurate than interpolation or domain mapping
⚠️ Challenges
  • Needs a lot of training data
  • More computing than simpler methods
  • Harder to interpret: we need tools to look inside
  • Its uncertainty maps have limitations

Step 0.1: A decision tree for regression

A regression tree asks a series of yes/no questions about the covariates, and each answer sends a site down one branch. At the end of a branch (a leaf), the prediction is the mean ⁸⁷Sr/⁸⁶Sr of the training sites that ended up there.

Each ball below is a training site, coloured by its ⁸⁷Sr/⁸⁶Sr (yellow = low, red = high). Hover over a ball to see its values. Choose the covariate used at each split, and watch the sites fall into the branches. Each leaf predicts the mean of its sites.

The menus only work on this website, not in RStudio.

splitOptions = new Map([["Let the tree choose", "auto"], ["Rock age", "age"], ["Distance to coast", "dist"], ["Rainfall", "rain"]])
viewof split1 = Inputs.select(splitOptions, {label: "Top split"})
viewof split2 = Inputs.select(splitOptions, {label: "Left split"})
viewof split3 = Inputs.select(splitOptions, {label: "Right split"})
toyTree = (() => {
  const mulberry32 = a => function(){a|=0;a=a+0x6D2B79F5|0;let t=Math.imul(a^a>>>15,1|a);t=t+Math.imul(t^t>>>7,61|t)^t;return((t^t>>>14)>>>0)/4294967296}
  const VARS = [
    {key:"age",  label:"Rock age",          unit:"Myr", fmt: v => Math.round(v)},
    {key:"dist", label:"Distance to coast", unit:"km",  fmt: v => Math.round(v)},
    {key:"rain", label:"Rainfall",          unit:"mm",  fmt: v => Math.round(v)}
  ]
  // 32 sites: Sr rises with rock age (radiogenic) and away from the coast (less sea salt); rainfall is a distractor
  const r = mulberry32(7)
  const sites = Array.from({length:32}, (_, i) => {
    const old = i % 2 === 0, inland = Math.floor(i/2) % 2 === 0
    const age  = old ? 600 + r()*2400 : 5 + r()*250
    const dist = inland ? 80 + r()*300 : 2 + r()*45
    const rain = 200 + r()*700
    const sr = 0.7088 + (old ? 0.0075 : 0) + (inland ? 0.0032 : 0) + (old && inland ? 0.002 : 0) + age*0.0000008 + (r()-0.5)*0.0034
    return {id:i, age, dist, rain, sr}
  })
  const mean = p => p.reduce((s,d)=>s+d.sr,0)/p.length
  const sse  = p => { const m = mean(p); return p.reduce((s,d)=>s+(d.sr-m)**2,0) }
  function bestSplit(pts, key){
    const s = [...pts].sort((a,b)=>a[key]-b[key]); let best = null
    for (let i = 1; i < s.length; i++){
      if (i < 2 || s.length - i < 2 || s[i-1][key] === s[i][key]) continue
      const e = sse(s.slice(0,i)) + sse(s.slice(i))
      if (!best || e < best.sse) best = {key, t:(s[i-1][key]+s[i][key])/2, sse:e}
    }
    return best
  }
  function splitNode(pts, choice){
    if (pts.length < 4) return null
    const total = sse(pts)
    const cands = VARS.map(v => { const b = bestSplit(pts, v.key); return {v, b, gain: b ? 100*(1 - b.sse/total) : 0} })
    const pick = choice === "auto" ? cands.reduce((a,c)=> c.gain > a.gain ? c : a) : cands.find(c => c.v.key === choice)
    if (!pick || !pick.b) return null
    return {cands, pick, yes: pts.filter(d => d[pick.v.key] < pick.b.t), no: pts.filter(d => d[pick.v.key] >= pick.b.t)}
  }
  const LO = 0.708, HI = 0.7215
  function colour(v){ // yellow -> orange -> red (like the slide), no external library
    const t = Math.max(0, Math.min(1, (v-LO)/(HI-LO)))
    const stops = [[255,230,90],[246,150,40],[200,40,35]]
    const [a,b,u] = t < 0.5 ? [stops[0],stops[1],t/0.5] : [stops[1],stops[2],(t-0.5)/0.5]
    return `rgb(${a.map((x,i)=>Math.round(x+(b[i]-x)*u)).join(",")})`
  }
  function balls(pts, cx, y, w){
    const R = 7, gap = 17, cols = Math.max(1, Math.floor(w/gap)), sorted = [...pts].sort((a,b)=>a.sr-b.sr)
    const n = sorted.length, rows = Math.ceil(n/cols), width = Math.min(n, cols)*gap
    const out = sorted.map((d,i) => `<circle cx="${cx - width/2 + gap/2 + (i%cols)*gap}" cy="${y + R + 2 + Math.floor(i/cols)*gap}" r="${R}" fill="${colour(d.sr)}" stroke="#555" stroke-width="0.6"><title>87Sr/86Sr = ${d.sr.toFixed(4)} | age ${Math.round(d.age)} Myr | coast ${Math.round(d.dist)} km | rain ${Math.round(d.rain)} mm</title></circle>`).join("")
    return {svg: out, h: rows*gap + 4}
  }
  function nodeBox(pts, sp, cx, y, w){
    const b = balls(pts, cx, y + 8, w - 16)
    let h = b.h + 16, txt = ""
    if (sp){
      const lines = sp.cands.map(c => `<tspan font-weight="${c === sp.pick ? 700 : 400}" fill="${c === sp.pick ? "#1f4e6b" : "#6c757d"}">${c.v.label} ${c.gain.toFixed(0)}%</tspan>`)
      txt = `<text x="${cx}" y="${y + h + 14}" font-size="11" text-anchor="middle" fill="#6c757d">variance reduced by a split on:</text>` +
            `<text x="${cx}" y="${y + h + 28}" font-size="11.5" text-anchor="middle">${lines.join(`<tspan fill="#aaa"> · </tspan>`)}</text>`
      h += 32
    }
    return {svg: `<rect x="${cx - w/2}" y="${y}" width="${w}" height="${b.h + 16}" rx="10" fill="#f4f6f8" stroke="#1f4e6b" stroke-width="1.2"/>` + b.svg + txt, h}
  }
  function leafBox(pts, cx, y, w){
    const b = balls(pts, cx, y + 8, w - 16), m = mean(pts)
    return {svg: `<rect x="${cx - w/2}" y="${y}" width="${w}" height="${b.h + 40}" rx="10" fill="#fff" stroke="${colour(m)}" stroke-width="3"/>` + b.svg +
      `<text x="${cx}" y="${y + b.h + 30}" font-size="13" font-weight="700" text-anchor="middle" fill="#8a3b12">mean = ${m.toFixed(4)}</text>`, h: b.h + 40}
  }
  function edge(x1, y1, x2, y2, label){
    return `<path d="M${x1} ${y1} L${x2} ${y2 - 18}" stroke="#7a8a96" stroke-width="1.6" fill="none" marker-end="url(#tt-ar)"/>` +
      `<text x="${x2}" y="${y2 - 4}" font-size="12.5" font-weight="600" text-anchor="middle" fill="#1f4e6b">${label}</text>`
  }
  function render(rootChoice, leftChoice, rightChoice){
    const W = 820, root = splitNode(sites, rootChoice)
    let svg = "", y0 = 10
    const rb = nodeBox(sites, root, W/2, y0, 330); svg += rb.svg
    const y1 = y0 + rb.h + 50
    const kids = [[root.yes, leftChoice, W/4], [root.no, rightChoice, 3*W/4]]
    const lab = (sp, yes) => `${sp.pick.v.label} ${yes ? "<" : "≥"} ${sp.pick.v.fmt(sp.pick.b.t)} ${sp.pick.v.unit}`
    svg += edge(W/2 - 60, y0 + rb.h + 2, W/4, y1, lab(root, true))
    svg += edge(W/2 + 60, y0 + rb.h + 2, 3*W/4, y1, lab(root, false))
    let leaves = [], maxH = 0, parts = []
    for (const [pts, ch, cx] of kids){
      const sp = splitNode(pts, ch), nb = nodeBox(pts, sp, cx, y1, 300)
      parts.push({pts, sp, cx, nb}); maxH = Math.max(maxH, nb.h)
    }
    const y2 = y1 + maxH + 50; let leafH = 0
    for (const p of parts){
      svg += p.nb.svg
      if (!p.sp){ leaves.push(p.pts); continue }
      for (const [sub, dx, yes] of [[p.sp.yes, -100, true], [p.sp.no, 100, false]]){
        svg += edge(p.cx + (yes ? -30 : 30), y1 + p.nb.h + 2, p.cx + dx, y2, lab(p.sp, yes))
        const lb = leafBox(sub, p.cx + dx, y2, 190); svg += lb.svg; leafH = Math.max(leafH, lb.h); leaves.push(sub)
      }
    }
    const r2 = 100*(1 - leaves.reduce((s,p)=>s+sse(p),0)/sse(sites))
    const H = y2 + leafH + 50
    // legend
    let leg = `<text x="20" y="${H-18}" font-size="12" fill="#333">⁸⁷Sr/⁸⁶Sr</text>`
    for (let i = 0; i <= 20; i++) leg += `<rect x="${80 + i*9}" y="${H-29}" width="9" height="12" fill="${colour(LO + (HI-LO)*i/20)}"/>`
    leg += `<text x="80" y="${H-4}" font-size="11" fill="#555">${LO.toFixed(3)}</text><text x="269" y="${H-4}" font-size="11" fill="#555" text-anchor="end">${HI.toFixed(3)}</text>`
    leg += `<text x="${W-20}" y="${H-18}" font-size="13" text-anchor="end" fill="#1f4e6b">Variance explained by the tree: <tspan font-weight="700">${r2.toFixed(0)}%</tspan></text>`
    return {r2, svg: `<svg viewBox="0 0 ${W} ${H}" style="width:100%;height:auto;font-family:'Source Sans 3',sans-serif" role="img" aria-label="Interactive regression tree"><defs><marker id="tt-ar" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto"><path d="M0,0L10,5L0,10z" fill="#7a8a96"/></marker></defs>${svg}${leg}</svg>`}
  }
  return {render, VARS}
})()
{
  const out = toyTree.render(split1, split2, split3)
  const div = document.createElement("div")
  div.innerHTML = out.svg
  return div
}

A toy dataset of 32 sites: ⁸⁷Sr/⁸⁶Sr is higher on old rocks (radiogenic) and far from the coast (less sea-salt Sr). Rainfall is unrelated to ⁸⁷Sr/⁸⁶Sr here. Under each node: how much a split on each covariate would reduce the variance of ⁸⁷Sr/⁸⁶Sr.

Things you might have noticed
  1. Rock age first: it reduces the variance the most (79%), because the largest contrast in ⁸⁷Sr/⁸⁶Sr is between old radiogenic rocks and young rocks. Then distance to coast on both sides. The four leaves are almost pure in colour: the tree explains 97% of the variance.
  2. With rainfall, every leaf mixes yellow and red balls: a covariate unrelated to ⁸⁷Sr/⁸⁶Sr gives poor splits, and the tree explains only ~15% of the variance. That is why we choose covariates by process.
  3. Yes: the same four groups and the same 97%, reached by another route. Very different-looking trees can give the same predictions, so don’t over-interpret the structure of a single tree.
  4. Age alone explains ~83%: the tree can’t separate coastal from inland sites, so it misses the sea-salt effect. Bioavailable Sr needs several covariates for several processes.

How does the tree choose its questions? At each node, the algorithm tries every covariate and every possible threshold (that is what “Let the tree choose” does above), and keeps the split that makes the two groups as homogeneous as possible (the largest drop in the variance of ⁸⁷Sr/⁸⁶Sr). It repeats this in each group until the groups are small.

Problems with a single tree
  • Overfitting: a deep tree ends up memorising the training sites, noise included.
  • Instability: add or remove a few sites and the whole tree can change.
  • Blocky predictions: a tree predicts one value per leaf, so a single-tree isoscape would be a patchwork of flat zones with sharp steps.
  • Greedy splits: each split is the best now, not necessarily the best for the whole tree.

Step 0.2: Bagging, many trees on resampled data

Bagging (bootstrap aggregation) grows many trees, each on a different bootstrap sample of the sites: sites drawn at random with replacement, so each tree sees about two-thirds of them (some twice), and never sees the remaining third. The prediction is the average of all trees. Averaging cancels out much of the noise each tree has memorised.

Step 0.3: Random forest, adding randomness to the splits

A random forest is bagging plus one more trick: at each split, a tree may only choose among a random subset of the covariates (mtry of them). This stops every tree from starting with the same strong covariate, so the trees are more different from each other, and their average is more robust.

💡 The out-of-bag (OOB) error

Each site is left out of about a third of the trees. Predicting each site with only the trees that never saw it gives a free estimate of the error, the OOB error, without a separate test set. VSURF uses it to rank the covariates (Step 4.3). But the OOB sites are scattered among the training sites, so the OOB error behaves like a random cross-validation: it is optimistic for spatial data (Step 4.2).

Step 0.4: See it for yourself

A toy example: 120 sites where ⁸⁷Sr/⁸⁶Sr rises with distance from the coast (less sea-salt Sr) and jumps at 260 km where the bedrock changes. Move the sliders.

The sliders only work on this website, not in RStudio.

viewof ntree = Inputs.range([1, 200], {value: 1, step: 1, label: "Number of trees"})
viewof depth = Inputs.range([1, 10], {value: 8, step: 1, label: "Maximum tree depth"})
viewof showTrees = Inputs.toggle({label: "Show the individual trees", value: true})
rf = {
  const mulberry32 = a => function(){a|=0;a=a+0x6D2B79F5|0;let t=Math.imul(a^a>>>15,1|a);t=t+Math.imul(t^t>>>7,61|t)^t;return((t^t>>>14)>>>0)/4294967296}
  const gauss = r => {let u=0,v=0;while(u===0)u=r();while(v===0)v=r();return Math.sqrt(-2*Math.log(u))*Math.cos(2*Math.PI*v)}
  const truth = x => 0.7092 + 0.009*(1-Math.exp(-x/60)) + (x>260 ? 0.006 : 0)
  const r0 = mulberry32(42)
  const sites = Array.from({length:120}, () => { const x = 10 + r0()*380; return {x, y: truth(x) + 0.0015*gauss(r0)} })
  function buildTree(pts, d, minLeaf){
    const mean = pts.reduce((s,p)=>s+p.y,0)/pts.length
    if (d===0 || pts.length < 2*minLeaf) return {leaf:true, value:mean}
    const s = [...pts].sort((a,b)=>a.x-b.x)
    let best=null, bestSSE=Infinity, sumL=0, sqL=0
    const tot=s.reduce((a,p)=>a+p.y,0), totSq=s.reduce((a,p)=>a+p.y*p.y,0)
    for (let i=0;i<s.length-1;i++){
      sumL+=s[i].y; sqL+=s[i].y*s[i].y
      const nL=i+1, nR=s.length-nL
      if (nL<minLeaf || nR<minLeaf || s[i].x===s[i+1].x) continue
      const sse=(sqL-sumL*sumL/nL)+((totSq-sqL)-(tot-sumL)**2/nR)
      if (sse<bestSSE){bestSSE=sse; best=(s[i].x+s[i+1].x)/2}
    }
    if (best===null) return {leaf:true, value:mean}
    return {leaf:false, t:best, left:buildTree(s.filter(p=>p.x<=best),d-1,minLeaf), right:buildTree(s.filter(p=>p.x>best),d-1,minLeaf)}
  }
  function predict(n, x){ return n.leaf ? n.value : predict(x<=n.t ? n.left : n.right, x) }
  function grow(ntree, depth){
    return Array.from({length:ntree}, (_,k) => { const r=mulberry32(1000+k); return buildTree(Array.from({length:sites.length}, () => sites[Math.floor(r()*sites.length)]), depth, 3) })
  }
  return {sites, truth, predict, grow}
}
grid = Array.from({length:201}, (_,i)=>i*2)
trees = rf.grow(ntree, depth)
forestLine = grid.map(x => ({x, y: trees.reduce((s,t)=>s+rf.predict(t,x),0)/trees.length}))
treeLines = showTrees ? trees.slice(0,30).flatMap((t,k) => grid.map(x => ({x, y: rf.predict(t,x), tree:k}))) : []
truthLine = grid.map(x => ({x, y: rf.truth(x)}))
rmse = Math.sqrt(grid.reduce((s,x,i)=>s+(forestLine[i].y-rf.truth(x))**2,0)/grid.length)

md`**${ntree === 1 ? "One tree" : ntree + " trees"}**, depth ${depth} · error against the true curve (RMSE) = **${rmse.toFixed(4)}**`
Plot.plot({
  height: 360, marginLeft: 60,
  x: {label: "Distance to the coast (km)", domain: [0, 400]},

🧩 Your turn
  1. With 1 tree and depth 8, how does the prediction look? Does it follow the noise or the true curve?
  2. Increase the number of trees to 50, then 200. What happens to the blue line and to the RMSE?
  3. With 200 trees, set the depth to 1, then 2, then 4. What goes wrong when the trees are too shallow?
Things you might have noticed
  1. One deep tree is a staircase that chases individual sites: it overfits the noise.
  2. Averaging many trees smooths the staircase and brings the prediction closer to the true curve: the RMSE drops. Beyond ~50 trees it barely changes, which is why a few hundred trees are enough.
  3. Very shallow trees can’t capture the shape (a depth-1 tree has only one step): the forest underfits. Random forests usually grow deep trees and let averaging remove the noise.

Notice also the edges: beyond the last site (here near 0 and 390 km), the prediction is flat. A random forest cannot extrapolate beyond the range of its training data.

Step 0.5: From a forest to an isoscape

For an isoscape, each “site” is a training sample with its ⁸⁷Sr/⁸⁶Sr and the values of ~60 covariates under it. Once the forest is trained, we give it the covariates of every 1 km pixel and it predicts ⁸⁷Sr/⁸⁶Sr there.

And the uncertainty? Each tree gives its own prediction for a pixel. A quantile random forest keeps the whole spread of training values in the leaves, not just their mean, so we can read the 15.9% and 84.1% quantiles and turn them into a standard deviation. That is our uncertainty map (Section 6).

Key words for today

Term Meaning In the script
Bootstrap sample Sites drawn at random with replacement; each tree gets its own done by ranger
OOB error Error on the sites a tree never saw; behaves like random CV used by VSURF
num.trees Number of trees in the forest 500–1000
mtry Number of covariates a split can choose from tuned in Step 4.6
min.node.size Minimum number of sites in a leaf tuned in Step 4.6
Variable importance How much the error grows when one covariate is shuffled Step 4.8
Partial dependence Prediction as one covariate varies, others averaged Step 4.8
Quantile random forest Keeps the spread in each leaf, to map uncertainty quantreg = TRUE

Summary

Key takeaways
  • A regression tree splits the sites with yes/no questions on the covariates; each leaf predicts the mean ⁸⁷Sr/⁸⁶Sr of its sites.
  • One tree overfits and is unstable. Bagging averages many trees grown on bootstrap samples; random forest also randomises the covariates at each split.
  • The OOB error is a free error estimate, but it behaves like random cross-validation.
  • Random forests cannot extrapolate beyond their training data.
